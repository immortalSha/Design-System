01 — The problem

Twelve teams, twelve versions of the same button.

Before the system existed, every module was effectively being redesigned from scratch — in parallel, under migration pressure, with no shared visual or component language holding it together.

FRAGMENT / 01

Recurring patterns — tables, alerts, status indicators — rebuilt slightly differently in every module, with no single source of truth.

FRAGMENT / 02

Users moving between modules met inconsistent visual treatment and interaction patterns for the same underlying task.

FRAGMENT / 03

No shared specs meant engineers interpreted one-off designs screen by screen — slow handoff, avoidable rework.

FRAGMENT / 04

Accessibility was checked at final QA, not designed in — a real risk on a healthcare platform serving a wide range of users.

FRAGMENT / 05

The Pega → AWS migration meant this had to be solved while the platform was actively being rebuilt — not before.

FRAGMENT / 06

Ambiguous, module-specific requirements made it hard for any one team to define what "consistent" should even mean.

02 — The process

Building governance in, not bolting it on.

A system only works if the teams around it can adopt it without a bottleneck. Each stage below was built to hold up on its own once I stepped back.

01

Audit & pattern discovery

Mapped recurring UI patterns across all 12 modules — navigation, tables, forms, status states — to find what needed systemizing first.

02

Stakeholder alignment

Ran workshops with Business Analysts, Architects and Developers to turn ambiguous module requirements into shared flows a common component set could support.

03

Building the system in Figma

150+ components, 1,000+ variants, and a token architecture so visual updates propagate system-wide instead of screen by screen.

04

Accessibility by design

WCAG 2.1 AA — keyboard navigation, screen reader support, color contrast — validated at the component level, not caught at final QA.

05

Documentation & governance

Usage guidelines, state documentation and accessibility notes shipped with every component, so other designers could adopt it independently.

06

Validation

Usability testing and heuristic evaluation pressure-tested components before rollout, catching issues before multiple teams built on top of them.

03 — The impact

What changed once teams shared one system.

The system became the shared design language for the platform migration — not a side deliverable, but the thing multiple teams built on top of.

–Reduced duplicate design effort across product teams by replacing one-off, per-module builds with a shared component library.
–Improved consistency for 100K+ users, even as the underlying platform was migrated from Pega to AWS.
–Faster design-to-engineering handoff through documented components, tokens, and Figma Dev Mode.
–Accessible by default — WCAG 2.1 AA embedded in components, not caught late in QA.
–Let the legacy-to-cloud migration proceed without disrupting the experience for existing users.
04 — What I learned

The system's real test wasn't the component count.

"A design system earns its keep when other designers can pick it up correctly without you in the room."

"Governance has to be built alongside the system — bolt it on later and it fragments right back into one-offs."

"Fixing accessibility once in a component is cheaper than fixing it a dozen times downstream."

"Rolling this out mid-migration meant sequencing and stakeholder communication mattered as much as the design itself."
